# Marketing creative

Meta ads, flyers, posters and other campaign pieces are built here as plain HTML, designed with the Impeccable skill, and rendered to PNG or PDF with headless Chrome.

## How the pieces fit

```
marketing/
├── PRODUCT.md            Impeccable's product record for marketing: audiences, channels, claims rules
├── DESIGN.md             Visual system, recorded from the storefront so ads match the website
├── .impeccable/          Impeccable's own files (design.json sidecar, per-asset briefs)
├── creative/
│   ├── README.md         This file
│   ├── formats.md        Canvas sizes, safe zones, bleed, print notes
│   └── kit/              Shared by every asset
│       ├── brand.css     Outfit @font-face and the CI colours as --cs-* variables
│       ├── canvas.js     Sizes the canvas from data-canvas, sets print bleed, ?guides overlay
│       ├── fonts/        Outfit Regular, Medium, SemiBold, Bold
│       ├── logo/         logo-on-navy.png, logo-on-white.png
│       └── illustrations/  Brand illustrations as SVG (robots, atoms, planets, ...)
├── campaigns/
│   ├── _template/        Copy this to start a campaign (brief.md, asset.html)
│   └── <yyyy-mm-slug>/   One folder per campaign
│       ├── brief.md      Audience, offer, dates, facts, landing URLs, ad copy
│       ├── *.html        One file per asset
│       ├── images/       Photos and QR codes this campaign uses
│       ├── exports/      Rendered PNG/PDF, generated by render.sh
│       └── results.md    What happened, once it has run
└── scripts/
    ├── render.sh         HTML to PNG (screen) or PDF + preview (print)
    └── qr.sh             UTM-tagged QR code as SVG
```

Impeccable treats `marketing/` as its own project, separate from the storefront, because `marketing/PRODUCT.md` and `marketing/DESIGN.md` sit here. It picks them up whenever the target file is inside `marketing/`.

## Making a campaign

1. **Start the folder.** Copy the template and name it `<yyyy-mm>-<slug>`:

   ```bash
   cp -R marketing/campaigns/_template marketing/campaigns/2026-10-holiday-sale
   ```

2. **Fill in `brief.md`.** Audience (parents *or* educators), the one action, the offer, and the facts with their sources. Impeccable reads this; the better the brief, the less it guesses.

3. **Bring in images.** Copy the product photos you want from `assets/product/<handle>/lifestyle/` (or `end-user/`) into the campaign's `images/` folder with descriptive lowercase names. Don't link to `assets/` directly; the campaign folder should render on its own.

4. **Design with Impeccable.** Name the asset file and canvas in the request so Impeccable loads the marketing context. For example:

   > /impeccable Design a Meta feed ad for the holiday sale in marketing/campaigns/2026-10-holiday-sale/feed-portrait.html, canvas meta-portrait. Brief is in brief.md in that folder.

   Impeccable runs its direction round and saves a surface brief for the asset in `marketing/.impeccable/`. Then it builds the HTML.

5. **Make the other sizes.** Once one asset is approved, ask for its siblings from it, so they share a look instead of each starting over:

   > /impeccable adapt marketing/campaigns/2026-10-holiday-sale/feed-portrait.html into story.html (canvas meta-story) and flyer-a5.html (canvas a5)

6. **Render and check.**

   ```bash
   marketing/scripts/render.sh marketing/campaigns/2026-10-holiday-sale/*.html
   ```

   Look at every export at real size: the PNGs on a phone, the `-preview.png` for print. Then run a refinement command if it needs one (see below).

7. **Ship it.** Upload the PNGs to Ads Manager with the copy from the brief. Send `<name>.pdf` (with bleed) to a print shop, or print `<name>-trim.pdf` in the office. Commit the campaign folder, exports included, so we have a record of what ran.

8. **Afterwards,** write `results.md`: spend, reach, CTR, and what PostHog shows for the campaign's `utm_campaign`.

## Useful Impeccable commands on an asset

| Command | When |
|---|---|
| `shape` | Before designing, to turn a loose idea into a confirmed brief |
| `critique` | A design review with scores, before you commit to it |
| `bolder` / `quieter` | It's too safe to stop a scroll, or it's shouting |
| `typeset` | The headline hierarchy isn't landing at thumbnail size |
| `layout` | Things feel cramped or the eye doesn't know where to go |
| `clarify` | The copy on the image needs tightening |
| `adapt` | Turn one approved asset into another canvas |
| `polish` | The last pass before rendering |

## Rules every asset follows

- **One reader.** Parents or educators, from the brief. Never both on one asset.
- **One action, one destination.** A single CTA, and a landing URL with UTM parameters that is actually live.
- **Facts from source.** Prices and sale percentages from Shopify, delivery numbers from `storefront/src/config/site.json`, testimonials from `storefront/src/components/HomeTestimonials.tsx`. Write each source into the brief.
- **Naming and money.** CREATESPACE in capitals. "Delivery" not "Shipping", "VAT" not "Tax". `R 1,499`.
- **Voice.** `assets/brand/voice-and-tone.md` applies to every word on the image. No em or en dashes. Finish with the `humanizer` skill.
- **Logos.** `logo-on-navy.png` on navy or dark photos, `logo-on-white.png` on white. Partner brand logos go on white only.
- **Assets stay here.** Everything an asset uses sits under `marketing/` so renders don't depend on the storefront or `assets/` being laid out the same way later.
